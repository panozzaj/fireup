FIREUP(1)                    User Commands                    FIREUP(1)

NAME
    fireup - local development server manager

DESCRIPTION
    fireup manages local development servers with automatic port
    allocation, subdomain routing (*.test), and a web dashboard.

    Dashboard: http://fireup.test

CONFIGURATION
    Config files are stored in ~/.config/fireup/

    SIMPLE COMMAND (recommended)
        Create a file with just a command. fireup assigns a dynamic port
        via $PORT, avoiding conflicts with other apps.

        Example: ~/.config/fireup/myapp
            rails server -p $PORT

    FIXED PORT PROXY (not recommended)
        A file containing just a port number proxies to that port.
        Fixed ports can conflict; prefer commands with $PORT.

        Example: ~/.config/fireup/legacy
            3000

    STATIC SITE (symlink)
        Symlink to a directory containing index.html.

        Example:
            ln -s ~/projects/my-site ~/.config/fireup/mysite

    YAML CONFIG
        For more options, use YAML format (appname.yml).

        Example: ~/.config/fireup/myapp.yml
            description: My Rails App
            root: ~/projects/myapp
            cmd: rails server -p $PORT -b 127.0.0.1
            env:
              RAILS_ENV: development
              DATABASE_URL: postgres://localhost/myapp_dev

    MULTI-SERVICE YAML
        For apps with multiple services (e.g., web + assets).

        Example: ~/.config/fireup/myapp.yml
            description: My Full-Stack App
            root: ~/projects/myapp
            services:
              web:
                cmd: rails server -p $PORT -b 127.0.0.1
                default: true
              assets:
                cmd: npm run dev
                env:
                  PORT: $PORT

        URLs:
          - http://myapp.test        -> web service (default)
          - http://assets-myapp.test -> assets service

YAML OPTIONS
    Root-level options:
        description   Human-readable app description
        root          Working directory (supports ~)
        cmd           Command to run (for single-service apps)
        env           Environment variables (map)
        alias         Single alias for the app
        aliases       List of aliases for the app
        static        Set to true for static file serving

    Service-level options (under services:):
        cmd           Command to run
        env           Environment variables (map)
        default       If true, this service handles the base domain
        depends_on    List of services that must start first

ENVIRONMENT VARIABLES
    fireup sets these variables for each process:

    PORT          The allocated port for this service. Your command should
                  listen on this port.

    FORCE_COLOR   Set to "1" to enable colored output in most tools.

    You can reference $PORT in env values:
        env:
          API_URL: http://localhost:$PORT/api

URLS AND ROUTING
    Apps are accessible at http://<appname>.test

    For multi-service apps:
        http://<appname>.test              -> default service
        http://<service>-<appname>.test    -> specific service

    Examples:
        http://blog.test                   -> blog app
        http://myapp.test                  -> myapp's default service
        http://api-myapp.test              -> myapp's api service

COMMANDS
    APP STATUS
        fireup status          List apps and their running status
        fireup status myapp    Filter to apps/services matching "myapp"
        fireup status --json   Output as JSON (same as /api/status)
        fireup list            Alias for 'status'

    APP CONTROL
        fireup start <name>    Start an app or service
        fireup stop <name>     Stop an app or service
        fireup restart <name>  Restart an app or service
        fireup logs [name]     View logs (server logs if no name specified)

    SETUP
        fireup setup           Interactive setup wizard
        fireup setup status    Show component status (ports, cert, service)
        fireup teardown        Remove all fireup configuration

    ADVANCED
        fireup serve           Start the server (usually runs as service)
        fireup ports           Manage port forwarding
        fireup cert            Manage HTTPS certificates
        fireup service         Manage background service
        fireup docs            Show this documentation

SERVICE NAME FORMATS
    For start/stop/restart, you can target individual services:

    myapp                 All services in the app
    myapp:worker          The 'worker' service (colon syntax)
    worker.myapp          The 'worker' service (dot syntax)
    worker                The service if name is unique across apps

VIEWING LOGS
    Server logs (request routing):
        fireup logs

    App logs:
        fireup logs myapp

    Follow logs in real-time:
        fireup logs -f myapp

    Show last N lines:
        fireup logs -n 50 myapp

    Logs are also visible in the dashboard at http://fireup.test

TROUBLESHOOTING
    "Address already in use"
        Another process is using the port. fireup allocates ports in the
        50000-60000 range. Check for orphaned processes:
            lsof -i :50000-60000 | grep LISTEN

    App won't start
        1. Check the app's logs: fireup logs <app>
        2. Verify the command works manually:
               cd /path/to/app && PORT=3000 <your-command>
        3. Ensure dependencies (node, ruby, etc.) are available

    "Connection refused" in browser
        1. Check if fireup is running: fireup setup status
        2. Check if port forwarding is set up: fireup ports install
        3. Verify DNS: ping myapp.test (should resolve to 127.0.0.1)

    HTTPS not working
        1. Run: fireup cert install
        2. Restart your browser completely (quit and reopen)
        3. Check certificate status: fireup cert status

    Changes to config not taking effect
        fireup watches config files and reloads automatically.
        If not working, restart the app: fireup restart <app>

    Environment not loading (rbenv, nvm, etc.)
        fireup runs commands in a login shell. Ensure your shell config
        (~/.zshrc or ~/.bashrc) sets up your environment correctly.

    Rails PID file conflicts
        fireup automatically removes stale tmp/pids/server.pid files
        before starting Rails apps.

TAILSCALE SERVE (REMOTE ACCESS)
    fireup supports Tailscale Serve for accessing your local services
    from other devices on your Tailnet (e.g., your phone).

    SETUP
        1. Install Tailscale and connect to your tailnet, on BOTH this
           machine and the device you want to access apps from.
        2. Expose fireup via Tailscale Serve:
               tailscale serve http://127.0.0.1:80

           Use whatever port fireup is listening on. It defaults to 80;
           if you started fireup with --http-port, match that instead.

        3. Access from any device on your tailnet:
               https://<machine-name>.<tailnet>.ts.net/<app-or-service>/

           Find <machine-name>.<tailnet> with `tailscale status --json`,
           or just `tailscale status` and read your own row.

    WHY USE THIS INSTEAD OF AN IP AND PORT
        fireup assigns each app a dynamic $PORT, so http://<tailnet-ip>:<port>
        is only correct until the next restart — ports are reallocated in
        start order and quietly move between apps. Tailscale URLs name the
        app instead, so fireup resolves the current port on every request and
        the URL never goes stale. This matters most for clients that store
        the address in a settings screen and fail silently, such as a phone.

    URL FORMAT
        For simple apps:
            https://macbook.tailnet.ts.net/blog/
            https://macbook.tailnet.ts.net/blog/posts/123

        For multi-service apps, use the service-app format:
            https://macbook.tailnet.ts.net/api-myapp/
            https://macbook.tailnet.ts.net/web-myapp/

        The path prefix is stripped before routing to your service.

    EXAMPLES
        # Expose fireup (run on your laptop)
        tailscale serve http://127.0.0.1:80

        # From your phone, access the api service of focustrack:
        https://macbook-pro.tail094a69.ts.net/api-focustrack/health

        # Access a simple app:
        https://macbook-pro.tail094a69.ts.net/blog/

    HOW IT WORKS
        When fireup receives a request from a *.ts.net host:
        1. It extracts the app/service name from the first path segment
        2. For "service-app" patterns (e.g., api-myapp), routes to that service
        3. For simple names (e.g., blog), it routes to the app
        4. The path prefix is stripped before forwarding

    INTERSTITIAL PAGES
        When a service is starting, fireup shows an interstitial page that
        polls for status. This works correctly over Tailscale - the page polls
        the same Tailscale URL rather than the local .test domain.

    RESERVED PATH PREFIXES
        The following path prefixes are reserved and cannot be used as app names
        when accessed via Tailscale:

            /api/     - Dashboard API endpoints

        If you have an app named "api", access it via the full service format
        (e.g., /api-myapp/) or rename it.

    STOPPING TAILSCALE SERVE
        tailscale serve reset    # Remove all serve configurations
        tailscale serve status   # View current configuration

    TROUBLESHOOTING
        Work outward from the machine running fireup — each check assumes
        the previous one passed.

        "No serve config" from `tailscale serve status`
            Nothing is exposed yet. Run the setup command above. Note that
            `tailscale serve` accepts a target port without validating that
            anything listens there, so a config pointing at the wrong port
            looks identical to a correct one in `status` output.

        Routing works locally but not from another device
            Confirm the remote device is actually on the tailnet:
            `tailscale status` lists peers, and a peer that has not connected
            in a while shows as "offline, last seen ...". Phones in particular
            drop off after an OS update or a long idle period, and the
            Tailscale app can be installed and logged out at the same time.

        "App not found" listing the available apps
            The first path segment did not match an app, an alias, or a
            service-app pair. The error page lists what is configured; check
            for a typo, and remember that multi-service apps need the
            service-app form (/api-myapp/, not /myapp/api/).

        Verifying without a second device
            Requests are routed on the Host header, so you can exercise the
            whole path from the fireup machine:

                curl -H 'Host: <machine>.<tailnet>.ts.net' \
                     http://127.0.0.1/<app-or-service>/

            A 200 here isolates the problem to Tailscale connectivity rather
            than fireup routing.

GLOBAL SETTINGS
    Global settings are stored in ~/.config/fireup/config.json

    Example:
        {
          "tld": "test",
          "claude_command": "claude",
          "ollama": {
            "enabled": true,
            "url": "http://localhost:11434",
            "model": "llama3.2"
          }
        }

    tld               Top-level domain for app URLs (default: "test")
                      Apps are accessible at http://<app>.<tld>

    claude_command    Command to run Claude Code for the "Fix with Claude
                      Code" button on error pages (default: "claude").
                      Set to the path or name of your Claude Code binary.
                      Leave empty or omit to disable the button.

    ollama            Local LLM for error log analysis on the dashboard.
        enabled       Enable Ollama integration (default: false)
        url           Ollama API URL (e.g., "http://localhost:11434")
        model         Model name (e.g., "llama3.2")

    Changes to config.json are picked up without restarting fireup.

FILES
    ~/.config/fireup/           App configuration directory
    ~/.config/fireup/config.json   Global settings (see GLOBAL SETTINGS)
    ~/.config/fireup/certs/     HTTPS certificates
    ~/Library/LaunchAgents/com.fireup.plist   Background service
    ~/Library/Logs/fireup/      Service logs
